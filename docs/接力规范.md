# 接力规范

驿窗「接力」：把一个发起会话（Claude Code / Codex）交来的一段话送到一个执行方（现在只有 ChatGPT 网页）去审，拿回回信、转回发起会话，往返直到通过、到顶或常浩叫停。

本文写**接力本身的规矩**，不绑某一家执行方。ChatGPT 网页这一家具体怎么做到，写在 [chatgpt-channel.md](chatgpt-channel.md)；常浩定过的每一条以 [DECIDED.md](DECIDED.md) 为准；为什么要写这份，见 [接力治本问题清单](design/接力治本-问题清单-2026-11-27.md)（#544）。

每一条后面标：**〔现行〕** 代码现在就是这样；**〔目标 #544-n〕** 还没做，由 #544 第 n 步做到。两者对不上时以代码为准，并在这里改标注。

## 1. 边界

- 执行方是别人的网页时，页面改版、掉登录、Chrome 没开、执行方自己出错，这几件事消除不了。接力能保证的是：**出了这些事，几分钟内在接力卡上写明是哪一种，并告诉发起会话**；不保证「永不坏」。
- 这份规范管「一段话从发起会话出发、到执行方、再回来」这一路。侧栏怎么画、审核门怎么判轮数，各有各的文档，这里只引用。

## 2. 角色

| 角色 | 是谁 | 负责 | 不负责 |
|---|---|---|---|
| 发起方 | Claude Code 或 Codex 会话 | 写送审包、调 `relay_to_chatgpt`、收到回信后改代码再送审 | 判断送没送到、回信是不是这一轮的 |
| 驿窗 | 本应用的 Rust 宿主（`src/crates/host/src/handoff/`） | 接力记录（唯一的账本）、每一步的编号和时限、判断这一步成了没有、出错时告诉卡片和发起方 | 读执行方的页面 |
| 执行方通道 | ChatGPT：Chrome 插件 + 页面脚本（`src/apps/chrome-extension/`），经 Native Messaging 连驿窗 | 打开会话、把话送进去、报「开始写 / 写完 / 没回 / 认不出」、按提问编号读回信 | 记账、判断要不要停 |
| 常浩 | — | 到顶、决策升级、送达状态说不清时拍板；手动暂停 / 继续 / 结束 | 盯着等回信 |

账本只有一份：`<数据目录>/chatgpt/handoffs.json`（状态与步骤）。`turns.jsonl`（执行方报的回合）、`postpane.log`（驿窗自己的报错）只是日志，不驱动任何决定。〔现行〕

## 3. 一段话的一生

| 步 | 谁做 | 唯一编号 | 算成了的依据 | 时限 | 超时 / 出错怎么办 |
|---|---|---|---|---|---|
| ① 发起 | 发起方 → 驿窗 | 接力 id（`h…`）；审查链 `chain`（`r…`） | 驿窗记下 `opening` 或续接到已开的接力 | MCP 等 55 秒 | 驿窗返回中文原因（插件没连、上一段还在送、到顶要授权等）〔现行〕 |
| ② 打开 / 送进去 | 驿窗 → 通道 | 请求号：打开 `接力id~第几次`，续送 `接力id~send时间`；送审包首行带【驿窗送审 …】 | 通道报 `opened` / `sent`，并带**提问编号** | 打开 2 分钟、送话 30 秒 | 通道明确说没点发送 → 没送成，可重送；说不清 → 「送达未确认」，驿窗自己去会话里找（最多 30 次），找不到交常浩并通知发起方〔现行 #466 #509 #524〕。迟到的成功照样补记、只记一次〔现行 #223〕；补告诉发起方「其实已送到」〔目标 #544-4〕 |
| ③ 开始写 | 通道 → 驿窗 | 提问编号 | `turn start` | — | 没有这一步也不算错（可能直接到 ④）〔现行〕 |
| ④ 写完 | 通道 → 驿窗 | 提问编号 + 回信编号（`messageId`） | `turn complete` 且提问编号等于 ② 记下的 | 现行：送达满 30 分钟后按信号判——最近 5 分钟内重读读到「在写」就继续等，最多等 2 小时；没信号满 30 分钟停下交常浩（停因和通知分「30 分钟没回信」「写到一半没了动静」「写了 2 小时还没写完」三种），侧栏同一刻改「未审」〔现行 #544-3，常浩 2026-11-27 回「改」〕；目标：执行方明确说这一轮没回答就立刻说明〔目标 #544-4〕 | 漏报时驿窗 3 分钟后开始重读，每 2 分钟一次、无果退避、最多 5 次后停读并在卡上说明〔现行 #356 #433；页面最新回答属于更早的提问时原来会清零计数、上限失效，2026-11-27 已修：没被收下的回信不算进展〕 |
| ⑤ 认领 | 驿窗 | 回信编号只记一次 | 提问编号对上；提问读不到（附件等）拒收并提示〔现行 #410 #431〕 | — | 认不出的原因要写进卡片：提问不在会话里 / 没回答 / 没画出 / 认不出〔目标 #544-3〕 |
| ⑥ 审核门 | 驿窗 | 受审提交 `head` | 末尾四行齐全、受审版本对上 | 补格式每封最多一次，没点发送 30 秒后再补一次〔现行 #347 #528〕 | 见 chatgpt-channel「审核门」 |
| ⑦ 转回 | 驿窗 → 发起方 | 固定 id：`接力id-b回信步序`（转回）/ `-a`（再审一轮） | 发起方插件领走并开始 | 签到过期马上重试一次；再失败排队；排队 3 分钟没领且会话停了就后台续接〔现行 #175 #255 #257〕 | 送不到不要求常浩点「转回」，自动重投直到送到〔目标 #544-4〕 |
| ⑧ 续审 / 到顶 / 结束 | 发起方再调 ① / 驿窗 | 同一接力、同一审查链 | 通过 → 转回并结束；返修 → 转回等下一轮；到顶、决策升级 → 转回并停、交常浩 | 交常浩的放 24 小时没动静自动结束 | 见 chatgpt-channel「自动往返」 |

## 4. 失败分三档

每个出错的地方都要归进一档，卡上和发起方收到的话按档来写。

1. **明确没成**（通道明确说没点发送、页面打不开、插件没连上）：不算送达，记一步原因，可以原样重送；驿窗能自己重试的自己重试，不停自动往返。〔现行：补格式 #528、送审没点发送 #466；其余各处 #544-4 收齐〕
2. **不确定**（点了没见开始、超时没回话、回信认不出）：先查清再决定——去执行方会话里按提问编号找，查清了按 1 或「已送达」走；查到上限仍不清楚才交常浩。不确定期间不重送，避免重复。〔现行：送审 #509 #524；回信那一侧 #544-3〕
3. **要常浩裁决**（到顶、决策升级、常浩暂停、查到上限仍不清楚）：才停自动往返，回信照样转回发起方并写明「下一步交常浩」。〔现行 #410 S1〕

停下的话必须说**哪一种、坏在哪、现在该谁做什么**，不能只写「超时」。〔目标 #544-2 #544-3〕

## 5. 不丢、不重复

- 每一段话都有唯一编号（第 3 节表里第 3 列）。同一编号再来一次，驿窗认出是同一段：已送到的不再送，只回「刚才已送到」。〔现行：送审「去重」、转回固定 id〕
- 发起方用同一请求号重送时幂等。〔目标 #544-4〕
- 回信按回信编号只记一次；全文先存 `replies/` 再截摘录。〔现行〕
- 每个「驿窗自己决定不再做」的地方都要写一行 `postpane.log`，并汇进每日自检。接力卡上驿窗自动记的停下（`stop`）和失败（`fail`）步——停读、放弃找、等回信到头、页面改版、排队过期等——已统一由一处写：每次改账本后比对各接力新增的这两种步骤，一步一行「PostPane stopped / gave up on handoff <编号>: <卡上那句>」（`handoff/notice/desk_log.rs`），不在各处单写〔现行 #544-5〕；影子读取停了还没写〔目标 #544-5，改 #488 已定内容，要先发改动确认〕；汇进每日自检〔目标 #544-6〕。

## 6. 认执行方页面的约定（网页类执行方）

- 依赖页面长什么样的东西（选择器、属性名、按钮文字、接口路径）只许写在适配文件里：ChatGPT 是 `src/apps/chrome-extension/page.js`（画面）和 `data.js`（页面自己的对话数据）。别处一律调用它们；`scripts/check-rules.mjs` 会查。〔现行 #548〕
- 适配文件要提供「页面体检」：把依赖的每一样逐项查一遍，返回缺哪几样。重读时跑，缺了报驿窗；同一张接力隔几分钟连续两次都缺，卡上写「ChatGPT 页面改版：驿窗认不出 X」、通知发起会话（不是没回信、别重送）、写一行日志。发送键、停止键只在用到时才出现，体检不查（送话时找不到发送键照旧报没点发送）。〔现行 #548：重读时；送话前沿用 `no-composer`；空闲时由每日自检跑，#544-6〕
- 测试夹具用真实页面的脱敏快照，不手写「以为页面长这样」；浏览器行为先在真实 Chromium 实测再写替身（L-51、L-69）。〔部分现行：`chromium.test.mjs`；快照 #544-6〕

## 7. 每日自检

每天用真浏览器对真执行方走一遍 ①～⑤，顺带页面体检、存快照、核对已装版本，结果进日志和体检。〔目标 #544-6，新建定时任务先问常浩〕

| 事件 | 一句话现状 | 空格数 |
|---|---|---|
| E1 迟到成功 | 迟到的打开、送到都能接上；判失败时已告诉会话的，之后不更正；打开新会话没有「点没点发送」 | 5 |
| E2 迟到回信 | 停下后到的照收照转回；接力已结束后到的只记日志 | 2 |

| E6 标签页回收 / 崩溃 / 错误页 | 回收、崩溃有真实 Chromium 测试；等回信时标签页被关，停因说成「30 分钟没回信」 | 3 |

| E10 页面认不出 | 重读时页面体检报缺项，连续两次就停下并写明认不出哪一样（#548）；停止键只在写回答时出现，体检查不了 | 5 → 1（#548 后剩停止键） |

| E13 重复送 | 送审、转回都去重 | 0 |
| E14 回程失败 | 重试、排队、后台续接都有；自动往返暂停时排进队列的转回没人管 | 1 |

## 9. 接一个新执行方要做的事

新执行方（另一个网页 AI、命令行、API）照下面实现一个通道，驿窗的账本、状态机、审核门、转回都不用改：

| 要实现的 | 说明 | ChatGPT 现在怎么做 |
|---|---|---|
| 打开会话 | 带请求号，成了报会话编号和提问编号 | 插件新开标签页、放进项目、送第一段 |
| 送话 | 带请求号；回「成了 + 提问编号」「明确没成 + 原因」「说不清」三种之一 | 粘贴分段、点发送、读新提问的编号 |
| 报回合 | 开始写、写完（带提问编号、回信编号）、没回这一轮、被停止 | `turn start` / `complete` / `stopped` |
| 按提问编号读 | 驿窗重读时，回「找到回信 / 提问不在 / 没回答 / 没画出 / 认不出」 | `reread` |
| 体检 | 报依赖的每一样还在不在 | `page.js` 的 `shape`，重读时带回 `missing`〔现行 #548〕 |
| 版本 | 连上时报自己的版本，驿窗比对 | 插件版本（#493） |

不是网页的执行方（命令行、API）没有「认页面」这一层，第 6 节可以跳过，但「三种送话结果」「按编号读」照样要有。
