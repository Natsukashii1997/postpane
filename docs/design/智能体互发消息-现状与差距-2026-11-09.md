## 一、用纸飞机把「结论」发给其他 AI，让 AI 之间互相对话

**上游怎么做**（`b1217c3`，说明在 `docs/agent-messages.md`）
- MCP 工具有四个，都在 `src/crates/messaging/src/tools.rs`：
  - `list_sessions`：列出本机的会话，带 id、客户端、标题、项目目录、状态（空闲 / 运行中 / 等审批）、能不能送达；
  - `send_message`：给某个会话发消息，可以带 `reply_to` 表示在回复哪条；
  - `start_session`：新开一个会话，算一次来回；
  - `get_message`：查一条消息的进度和对方的回答，只读已经采集到的会话记录，不唤醒对方。
- 「只发结论」不是程序强制的。工具说明写的是「What to send, whole」，驿窗也不截断文字。之所以只有结论，是因为工具根本不转发会话记录，发什么由发送方自己写。
- 消息格式在 `words.rs:48-95`：
  - 首行是 `[Agent HUD · 来自 Codex · 标题 · m-xxxx · 回复 m-yyyy]`；
  - 末行教对方用 `send_message` 回复；
  - 如果这条本身就是回复，末行改成「还需要再说时才回」，防止两边来回道谢。
- 发送方是谁由中转程序认定，不靠参数：Claude 取 `CLAUDE_CODE_SESSION_ID`，Codex 取 `_meta.threadId`（`src/apps/mcp/src/host-tools.ts`）。
- 送达方式分客户端：
  - Claude 和 DeepSeek：经插件签到加取件，等会话空闲再提交；
  - Codex：用 `thread/queue/add`；
  - Antigravity：经 language server。
- 回执只存指纹，结果不明的不重发（`src/crates/platform/src/delivery/`）。
- 纸飞机每来回一次飞一趟；被拒收的半路掉落（`flights.rs`、`FlightLayer.tsx`）。

**驿窗现在有什么**
- 只有一种接力：Claude 把说明和改动摘要发给 ChatGPT 网页审核，再把回信转回 Claude。入口是 MCP 工具 `relay_to_chatgpt`（`src/crates/host/src/handoff.rs` 的 `relay`）。
- 发给 ChatGPT 的不是「一条结论」，而是说明加改动摘要，因为 ChatGPT 读不到本机文件。这是 ChatGPT 网页这个通道的特点，不是缺陷。
- 本机 Claude 和 Claude、Claude 和 Codex 之间**完全不能直接发消息**：没有 `messaging` crate，也没有 `list_sessions`、`send_message`、`get_message` 这几个工具。
- 往 Claude 送话的底层已经有了，而且比上游多一步：
  - 插件取件，等空闲才提交；
  - #255：会话不在线也能排队；
  - #257：回执跟到「排队中 / 已领取 / 已开始」；
  - 代码在 `src/crates/platform/src/claude_plugin/mod.rs`。
- 往 Codex 送话还没接（#253 开着，已改成走队列方案）。

**差距**：缺一整套「本机智能体互发消息」，包括工具、发件人认定、链和轮次、日志、Codex 收件。Claude 收件这一端现成可用。

**建议做**。和接力分开，单独做成「互发消息」：
- 接力是有角色、有轮次、有时间线的审核流程，已经定稿，保持不动；
- 互发消息是轻量的点对点消息。

第一步只做 Claude ↔ Claude，因为 Claude 收件、排队、回执都现成；第二步加 Codex 收件和发件（就是 #253 的结论）。Antigravity、DeepSeek 不做。`start_session` 先不做：常浩在 Claude 桌面版里有自己的交接卡流程，智能体自己开新会话会绕开它。

## 二、对方正忙时，纸飞机在旁边等着：可以多开任务了，还有没有价值？

**判断**：要拆成两件事看。

1. **「排队等对方这一轮做完再送进去」：有价值，而且必须有。** 理由有三条：
   - **结论得回到那个已经有上下文的会话里。** 视频里 Claude 已经用了 182K 上下文，Codex 也已经审过一轮，第二次审查交给同一个 Codex 才有意义。另开一个新任务，等于让新会话从头再读一遍项目，省掉的上下文和 token 又花回去了。而且回信得送回发起方原来那个会话，新任务接不住。
   - **不能插进正在跑的那一轮。** 对方正在改文件、跑测试，中途插话会打乱它手上的活。上游刻意只用队列，不用 `steer`，原因就在这里（`docs/agent-messages.md` 第 34 行）。
   - **多开任务解决的是另一类事**：和对方手上的活无关、又不需要它的上下文的独立任务。这种情况开新会话更好，上游也为它准备了 `start_session`。两条路互补，谁也替代不了谁。
2. **「纸飞机停在对方旁边、标着排队中」这个画面：价值低，不建议做。**
   - 上游代码里本来就没有这个画面，只出现在视频里。
   - 驿窗已经能在接力卡时间线上显示「排队中 / 已领取 / 已开始」（#257），状态是看得到的。
   - 侧栏上再加一个常驻的等待信封，会改动已经定稿的纸飞机加印章动效（见第五节），换来的信息却和时间线重复。

**驿窗现在的程度**：往 Claude 送话已经是「等空闲才提交」，会话不在线也能排队（#255）。往 Codex 送话还没有。所以真正缺的只是 Codex 那一端的队列（#253）。

## 三、所有 agent 在同一个项目目录工作：项目本身就是上下文，不传完整对话

**上游怎么做**
- 没有专门的机制，靠的是约定：
  - `list_sessions` 返回每个会话的项目目录；
  - `start_session` 默认开在发送方的项目目录里，只能开在用户用过的目录（`startFolders`）。
- 发消息时不检查双方是不是同一个目录，不转发会话记录，只送发送方写的那段话。

**驿窗现在有什么**
- 接力给 ChatGPT 要带改动摘要，因为 ChatGPT 读不到本机文件，常浩 2026-11-05 已经定过。
- 本机智能体之间还没有传话，所以这一点暂时谈不上「有」或「没有」。

**差距，也是驿窗特有的坑**：
- 驿窗规定**并行会话各开独立 worktree**（AGENTS.md「分工」、全局坑 G-04）。Claude 在 `.claude/worktrees/xxx` 里改的东西，提交之前，开在主目录的 Codex 是看不到的。「同一个项目目录」在驿窗不是自然成立的。
- 只传「审一下 token.ts」，Codex 会去主目录读旧代码，审错版本。

**建议做，而且要比上游多做一步**：
- 驿窗本来就知道每个会话的工作目录。发消息时，自动在首行标签后面加一行「位置」，写上发送方的工作目录、分支和当前提交（`HEAD` 短号），有没有没提交的改动也一起写。
- 接收方据此去读对应的 worktree 或分支，「项目本身就是上下文」才真正成立。
- 这样仍然不传会话记录，也不用发送方自己记得写路径。

### 「以我的身份发送」的注意事项（驿窗特有）

1. **「Claude 先问用户再合并」是模型自己的判断，程序不强制。** 上游代码里没有任何「先问用户」的拦截，只靠首行标签让接收方知道「这话不是常浩说的」。打开这个开关就等于把标签摘掉。
2. **驿窗的环境更危险。**
   - 常浩的 Claude 会话常用 bypass 权限模式（本会话就是）。
   - 记忆里还有「测试全过可直接 squash 合并」的授权。
   - 所以打开以后，另一个智能体写一句「合并吧」，接收方会当成常浩本人的话执行，没有任何一道闸。
3. **和常浩已经定下的规则会冲突。** P-14 和 AGENTS.md 要求：已定内容要改，必须常浩本人明确回复。如果打开了以我的身份发送，智能体之间传的「确认」看起来和常浩本人说的一模一样，接收方分辨不出来。
4. **建议做法**：
   - 照上游加开关，默认关，标「注意」；
   - 驿窗这边仍然在日志和侧栏上留痕，记下「这条以常浩身份发出，发件人是谁」，符合 P-13「每条 AI 产出留痕」；
   - 设置页的说明里写明上面第 2、3 条。
   - 要不要更进一步，比如以常浩身份发出的消息里不允许出现「合并 / 删除 / 推送」这类词，这一条是推断，请常浩定。

### 设置页放哪

- 驿窗「智能体插件」页现在那一节标题是「让智能体调整侧栏」（`ToolsSection.tsx:31`），里面只有一个开关。要放进四个开关，标题得改成「智能体工具」之类的名字。这是文案改动，按 P-14 要先问常浩。
- 「AI 接入」页的「对外开放」要加一条「互发消息」：对谁开放、能读什么、能写什么、在哪里关掉。AGENTS.md「AI 接入」一节要同步改（P-13）。
