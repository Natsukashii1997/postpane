## 准入
准入：A｜发起
待决问题：把 Claude、Codex、ChatGPT、DeepSeek 统一成「工作场所」——同一数据对象 + 四层界面（票根 / 外层展出面板 / 内层接力面板 / 悬停）+ 个性化白名单 + 契约测试，Hermes 另列「飞书工作台」——这个结构方向和分批顺序对不对，C1–C7 推荐是否站得住。
当前判断与依据：方向成立。证据是前端各层大多已共用组件，但每家数据在 `model.ts` 各算一套，等你 / 在跑 / 刚回复 / 接力在各层有缺（对照矩阵），同一类问题在 LESSONS 里已逐家各修过 7 类。
理由：一级（重大架构路线、跨前后端多模块，错了要大范围返工）；常浩点名「先送 GPT 评审」；关键前提（ChatGPT 与另外三家是否真能同构、等你去留规则）尚未独立论证。

## 继承的结论（本次不重开）
- D1 四家是同一种性质「我的工作场所」，Hermes 单独一类（常浩 2026-11-14 原话）。
- D2 别家回复 4 秒收起、Hermes / ChatGPT 看过才收（常浩定，记忆 postpane-side-reply-4s）。
- D3 进出接力是卡头同一个白色纸飞机方块，印章左边（#341 / #344，2026-11-14 验收）。
- D4 侧栏小人保持动态（2026-11-09 #264 回归后常浩明确）。
- 已定内容要改先单独确认；UI 每次出三版预览（AGENTS.md）。

## 评审经过
### 第 1 次接力（2026-11-14，第一阶段，接力单 h1a1d8c8a62905）
- 本次解决了什么：确认四家同构方向与 Hermes 单列；把方案从「同构展示规范」收缩为「工作场所契约 Lite」；补出身份分层、能力的可观察性、「待核对」状态、验收前置四个缺口。
- 对重要意见的处理：
  1. 目标上提为「跨 AI 工作状态控制台」，成功标准加「可发现 / 可行动 / 可理解 / 可验证」——采纳。
  2. 能力区分「不支持 / 未启用 / 观察失联 / 正常无事」，失联不能显示成 0 或空闲——采纳。
  3. 工作场所 / 工作实例 / 观察通道分层；Codex App 与 `codex exec` 区分来源——采纳（快照已有 `origins` 字段可用，Claude 拉起的审查标 `sdk:claude`）。
  4. 接力是独立实体，各家按参与关系引用，角色属于接力记录——采纳；后端 `handoffs.json` 本来就是一单一条，改动主要在前端按参与关系过滤。
  5. 四层改为「操作路径（票根 → 展出卡 → 接力卡）+ 并行的概览通道（小收据、看板）」——采纳。
  6. 白名单只约束共用界面，来源适配器可按协议分支——采纳。
  7. 契约测试从小范围起步（语义一致、观察器不互相覆盖、等你不静默消失、接力不串线、失联不当空闲），另配固定场景的界面回归——采纳。
  8. 「等你」三态：等你 / 待核对 / 已处理——采纳。部分不采纳：「进程不存在不一定等于已处理」——对 Claude 钩子审批保留 #251 的撤卡（常浩 2026-11-09 选 A+B），反证是钩子进程一没，这条审批就再也送不回去，请求本身已终止；只有「观察器失联 / 日志静默」进待核对。
  9. 不做 24 小时硬折叠与「一键清」；可手动忽略，忽略不改真实状态，有新证据再提示——采纳。
  10. 未读回复、刚完成、审核意见自动转回中、观察器不知道的都不算「等你」——采纳。
  11. 顺序调整：阶段 0 先定契约与固定场景数据；独立 bug 先修，涉及状态语义的随数据统一一起修；验收手段前置——采纳。
  12. C1 采纳并保留全局「等你」汇总、跨家接力不重复计数；C2 限定为「关联接力入口」：只在本会话 / 本家有关联接力时出现，多条给列表；C3 采纳且失联不装 0；C5 采纳；C6 采纳并区分瞬时与持续阻断、按来源 + 工作 + 错误类型合并；C7 暂缓，先让看板能查到近期完成——全部采纳。
  13. 「注意力的最小单位是一件工作」：票根、小签、展出卡、看板读同一份工作项状态、同一优先级——采纳，写进契约。
  14. 三版预览只比布局与信息密度，状态语义先固定，三版用同一组场景数据——采纳。
- 评审出口：成熟退出

## 最终决策
- 选定路径及依据：「工作场所契约 Lite」。来源适配器（每家不同）→ 统一的前端派生视图 WorkspaceView（不落盘：身份、能力与观察健康、读数、工作项、接力关联）→ 现有共用组件。依据：组件已共用，缺口在数据派生与状态语义（审核报告 F1、F2、F6）。
- 接受的约束与风险：不建事件总线、持久化状态机、插件框架；C7 暂缓；悬停交互自动化可能仍有缺口，先用固定场景离屏渲染兜大部分。
- 执行中验证的假设：
  - F1 组件复用充分 —— 阶段 0 盘点；不成立就扩大界面统一范围。
  - F4 Codex 掉出主因是超时与观察器覆盖 —— 用固定场景复现 App 审批、exec 短会话、观察器失联；不成立先修观察通道。
  - DeepSeek 观察能力够用 —— 核对观察器与事件；不够就在外壳里标「不可观测」。
  - 接力能关联到具体会话 —— 核对接力记录里的会话 id 与多会话场景；不行就不出跳转入口。
  - 固定场景能替代大部分人工截图 —— 若只能验静态外观，再补 Tauri 交互测试。
- 常浩已裁决 / 待裁决：已裁决——C1、C2（修订）、C3、C4（修订）、C5、C6 按修订推荐，C7 暂缓（2026-11-14 侧栏回复「按修订推荐开工」）。可见界面变化仍先出三版预览。
- 执行边界：D1–D4 不动；接力审核门 #347 及其文件不碰；涉及已定内容的每项先拍板；可见 UI 变化先出三版。
- 重开条件：固定场景复现显示 Codex / DeepSeek 的观察通道无法提供工作项（契约假设不成立）；或常浩实际使用中仍频繁出现「该在却不在」的等待。
