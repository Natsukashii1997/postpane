# 卡片版式规范

侧栏所有卡片和面板（有待处理的卡、单家面板、整张看板、ChatGPT 卡、Hermes 卡）共用的版式规则。常浩 2026-11-15 定为应用级设计规范（#380）。

**什么时候读**：动侧栏任何一处界面之前，不论是加一种行、改一个签、换一个按钮，还是画预览、画规范版。还要读全局基础规范 `~/Documents/ChatGPT/个人/work/ui-system/docs/design-spec/DESIGN.md`（换任何风格都成立的对齐、间距、颜色规则）；两份冲突时以本文件为准，并报给常浩。

**交付前**：`pnpm run check` 里的 `check:card-layout` 会拦下本文件写明「机检」的几条（见下文「机器查的几条」）；它查不到的，按「怎么验」手量。

## 一套左对齐线

卡片内容区里只有两条左对齐线：

| 线 | 位置（从内容左边算） | 放什么 |
|---|---|---|
| 图标线 | 0 | 每行的图标（家的标记、在跑点阵、卡头小人）；没有自己图标的整块内容：分段标题（等待处理 · n、正在进行 · n）、额度说明和额度条、单家卡上的余额 |
| 文字线 | 30 | 有图标的行的标题和下面几行字；卡头家名；「还有 n 条」「收起」；「暂无等待处理的事」「暂无在跑的会话」；看板上余额区块自带小标题时的余额数字 |

数值在代码里只有一处：`src/packages/hud/src/panel/theme.ts` 的 `GRID`（图标列 18、间隔 12、文字线 30）。组件引用 `GRID`，不另写缩进数字（机检）。

## 每种元素放在哪

卡片里的东西按「它表示什么」分五种，先认是哪一种，再按下表放。认的依据是含义，不是用哪个组件画的：`ApprovalTag` 既画章（「等你」）也画类型签（ASK、WAIT），换个文字就换了种类，位置也要跟着换。

| 种类 | 表示什么 | 例子 | 只能放在 | 不许 |
|---|---|---|---|---|
| 图标 | 谁、在什么状态 | 家的标记（Claude 小人等）、在跑的 3×3 方点、卡头小人、Hermes 机器人印章 | 图标列，每行第一格 | — |
| 章 | 这一行处理到哪了，中文一两个字 | 「等你」「已回」 | 图标列（下面「例外」第 1 条） | 写成英文代码；和图标放在同一行 |
| 类型签 | 这一条是哪一类事 | ASK、PLAN、REPLY、START、WAIT、BASH、EDIT 等英文大写签 | 文字列，**标题下面那一行的起点**（文字线），后面跟小字 | 进图标列（机检）；和标题放在同一行；另起一种形状或颜色 |
| 标题、小字 | 这一条是什么、细节 | 会话标题；「问你：……」；等了多久 | 文字列 | — |
| 按钮 | 能点的动作 | 继续、停止、提交、跳过、↗ 回到会话 | 行尾，或最后一行文字的右侧 | 做成类型签的样子（英文大写、彩色细框）；并排的字数不一样（「继续 / 不做了」） |

**同一种事，同一种行**：凡是「一条等你处理的事」，不管在「等待处理」「积压事项」还是交接卡里，都是同一种行：图标列放谁，第一行标题，第二行「类型签 + 小字」。新加一种这样的行，照着已有的 ASK、REPLY 行排，排完和它们上下对齐；要排得不一样，先问常浩。

**正反例**（2026-11-28 积压事项，常浩指出）：

- 错：WAIT 签顶替了「等你」章原来的位置，进了图标列，和 Claude 小人、在跑方点成了同一级；行的第一列为了放下它改成了 `auto`。规范版预览也是这么画的，常浩在一批 7 项里没看出来，做进代码后才指出。
- 对：图标列放积压事项自己的图标；第一行标题；第二行 WAIT 在文字线起点，后面跟「问你：……」小字，和上面 REPLY、ASK 行的签上下对齐。

## 例外

- 图标列放的是章而不是图标时（「等你」「已回」、Hermes 机器人印章），章比图标列宽，这一行的文字跟在章后面，不硬对文字线。常浩 2026-11-15 选「章留在图标列」。这条只管章：类型签不是章，「等你」改成 WAIT 这类改动，签要照上表挪到标题下面一行（常浩 2026-11-28：WAIT「要和 reply ask 上下对齐，在每一个任务的主标题下边」）。
- 账户多于一个时，每个账户小标题下的内容对齐那个小标题，不受本表约束。
- 居中排的组件（额度环、分段图）不适用。

## 画预览、规范版时

预览里的产品界面照真实组件的结构画：行的列宽、间隔、签的位置抄 `GRID` 和现有行（`permissions/ListCard.tsx` 的 `EntryRow`），不自己另写一套 CSS 排法。2026-11-28 的错就是先出在手写的规范版里（第一列 `auto`、WAIT 放第一格），常浩批了一整批，没单独看出这一处，照着做进了代码。所以：

- 预览里每加一种新行，旁边并排放一条现有的同类行（如 REPLY 行），让位置对不对一眼看得出；
- 预览说明里单独列一句「这一行的签放在哪一列」，不和别的改动混在一起批。

## 机器查的几条

`pnpm run check` 里的 `check:card-layout`（`src/tooling/check-card-layout.mjs`）查下面三条，任何一条不过整个检查失败。改动前就有的旧问题记在 `src/tooling/card-layout-baseline.json`，只许变少：修掉一处就跑 `node src/tooling/check-card-layout.mjs --update` 收紧。

1. **类型签不进图标列**：一行用网格排、第一列是图标列（`GRID.mark`、印章列或 `auto`）时，第一格只能放图标或章；放了类型签（`ApprovalTag` 的文字不是「等你」「已回」这类章）就报错。
2. **缩进只从 `GRID` 取**：这种行的图标列宽、列间隔，以及 `30` 这样的文字线缩进，不许直接写数字。
3. **类型签的颜色只从一个入口取**：`ApprovalTag` 画类型签时不许传自己的 `color`，颜色由签的种类决定（`tagColor` / `toneInk` 一处）；除那一处外，不许再写「`tone === "ask"` 就用红」这种按种类挑颜色的分支。

机器查不了、交付前要自己看的：类型签的左边是不是正好在文字线（场景预览台里量 `getBoundingClientRect().left`，和同一张卡里 REPLY、ASK 签比）；按钮和签是不是一眼分得开；并排按钮、菜单项的字数是不是一样。

## 怎么验

改了卡片或面板版式，交付前在场景预览台（`pnpm --filter @agent-hud/hud run scenes`，127.0.0.1:1480）用页面脚本量各块图标和文字的左边（`getBoundingClientRect().left`），至少看 `claude-busy`（单家面板）、`claude-many-asks`（有待处理的卡）、`chatgpt-reviews`、`all-running` 的 DeepSeek 与 Hermes、`claude-busy` 看板。所有图标的左边一致、所有标题文字的左边一致，才算对齐。
