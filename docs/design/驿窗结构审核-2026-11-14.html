驿窗结构审核

四家「工作场所」现在共用了大部分组件，但没有共用同一个结构：每家的数据各算一套，「等你 / 在跑 / 刚回复 / 接力」四样东西在各层里有的有、有的缺。下面是证据、29 条问题、统一方案、需要你拍板的 7 项和分批计划。

GPT 评审后的修订（以本节为准）

ChatGPT 第一阶段思维评审：成熟退出。方向认可；方案从「四家同构的展示规范」收缩为「工作场所契约 Lite」：统一的是使用方式和状态含义，不是每家的全部能力。下方原有的「拍板项」「分批计划」被本节取代。

结构
来源适配器（每家按自己的协议读，可以分支）→ 统一的前端视图（不存盘：身份、能力与观察健康、读数、工作项、接力关联）→ 现有共用组件。不建事件总线、状态机框架、插件框架。
身份分层
工作场所（Claude / Codex / ChatGPT / DeepSeek）→ 工作实例（会话，带观察通道：例如 Codex App 和 Claude 拉起的 codex exec 审查分开）→ 状态。接力是独立的一条记录，各家只显示自己参与的那部分，不复制。
能力四态
不支持 / 未启用 / 观察失联 / 正常无事。失联不显示成 0，也不显示成空闲；不支持的（如 ChatGPT 审批）不提示。
等你三态
等你：有明确请求、证据仍有效。待核对：观察器失联或日志静默，看不清。已处理：作答、撤回、确认终止（Claude 钩子进程已死仍算终止，保留 #251）。时间只影响排序，不决定去留。未读回复、刚完成、审核意见转回中都不算「等你」。
界面
操作路径：票根 → 展出卡 → 接力卡；概览通道：小收据、看板，和操作路径并行。各入口读同一份工作项、用同一优先级。
验收
状态契约测试（语义一致、观察器不互相覆盖、等你不静默消失、接力不串线、失联不当空闲）+ 固定场景数据离屏渲染各卡，提前到第一步做，减少要你截图的轮数。

一句话结论

你的判断成立问题出在结构上，不是某个组件。同一类问题已经在不同智能体上各修过一次，LESSONS 里能数出 7 类。
Codex 看不到不全是用得少提问或等审批超过 30 分钟就被当成「已放弃」，从侧栏掉出；Codex 钩子也没接「完成」和「提醒」。
接力入口只挂在一种卡上纸飞机只在待审批卡上；而且不分家，DeepSeek 的卡点进去是 Claude 的接力。
Hermes 本来就该单列它不进「等你」和接力，现状基本合理，只需从工作场所的规则里明确划出去。

统一方案：工作场所契约

把四家当成同一种东西：每家产出同一个数据对象，侧栏按同一套四层画；只在白名单里的地方允许个性化。Hermes 走另一套「飞书工作台」。

外层 · 展出面板纸飞机 → 接力 2
等你审批、提问、等你回复；不因时间消失
在跑卡底一段，含「接力排队中」
刚回复 / 出错回执；停留规则按家配置
没接上例：「Codex 的审批没接上 · 去设置打开钩子」
内层 · 接力面板纸飞机 ← 返回
只列本家参与的接力（发起方或执行方），时间线、意见、自动往返照现在的接力卡
谁有Claude、Codex（发起和执行）、ChatGPT（审核方）；DeepSeek 暂无接力时不出纸飞机
数据对象
每家一份：读数（额度 / 余额 / 今日对话）、等你、在跑、刚回复、出错、接力、能力表（能不能侧栏回复、能不能发起接力、通道接没接上）。前端只从它取，不再按智能体名分支。
第 1 层 票根
读数 + 状态章。个性化：小人、脚印内容。
第 2 层 外层
小签点开：卡头（本家印 + 纸飞机）→ 等你 → 在跑 → 刚回复。所有外层卡（待审批、回复、额度、单家面板）卡头都是同一个，纸飞机只进本家接力。
第 3 层 内层
接力面板，同一个纸飞机进出。
第 4 层 悬停
小收据每家加一行「等你 N · 在跑 N · 接力 N」；整张看板每家区块 = 读数 + 本家等你和在跑，ChatGPT 也有区块。
状态规则
「等你」只在回答、撤回、确认进程已死时消失；「在跑」超时每家显式写在一处；出错单独成态并出回执；补 Codex 的「完成」「提醒」钩子。
个性化白名单
小人与动效、印章颜色、脚印读数、ChatGPT 对话 / 审核两栏的内容、DeepSeek 余额、Hermes 整块。白名单外的分叉由一条契约测试拦住。
Hermes
飞书工作台：机器人在岗、定时任务、最近被问、断线细条；不进「等你」，不进接力。现状保留。
