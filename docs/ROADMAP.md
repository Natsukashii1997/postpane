# 驿窗 PostPane 路线

定位：守在屏幕边上的个人工作中枢。汇总 AI 助手的额度、实时状态、审批、提问和回复，能一键跳回会话；第三方应用只做一键唤起。

代码源自 Agent HUD `917df21`（见 `NOTICE`），不再与上游同步，允许大改。默认只做电脑版；涉及 UI 时每次出 3 版明显不同的方案并附可打开的预览。

## 已拍板（2026-11-04）

1. **旧功能背后保留、界面收拢**（2026-11-04 晚些时候改定，取代早先的“裁掉”）：上游的旧功能只要不影响，代码都留着，界面上不显示，需要时常浩再提。
   - 助手全部照常显示：Claude Code、Codex、Hermes、Grok Bot 置顶，其余进入默认折叠的“其他助手”；各助手开关保持现状，关掉的不在后台读取。
   - 中转站、价格、更新三个设置页藏起来，代码保留。
   - 统计里不显示成本数字，只看 token；API 余额类账户（如 DeepSeek）的余额、估算花费、日均消耗、预计耗尽照留（2026-11-04）。
   - iPhone/局域网已删（1-1），不恢复。
2. **改名范围**：标识定为 `app.postpane.mac`；历史数据迁到新目录保留；内部代码名 `agent_hud_*`、`@agent-hud/*` 暂不改。
3. **自建应用接入暂缓**：先做阶段 0–2，自建应用（牛马之家、数码世界）以后再议，已有的调研结论记在文末。（2026-11-05 已启动，见文末「自建应用接入」）

## 阶段

### 阶段 0 立规矩与基线

- 目标：能稳定构建，知道现状，项目协作骨架就位。
- 交付物：
  - `pnpm install` 后记录构建与测试基线（哪些原本就失败），写进 `docs/BASELINE.md` 或 LESSONS。
  - 用 `/project-starter` 铺 `AGENTS.md`、`docs/LESSONS.md`、交接模板（先列计划等确认）。
  - `digital-twin/projects.json` 登记提案（只出提案）。
  - 在现装的 `/Applications/Agent HUD.app` 上真实验证：Claude 发起权限请求 → 侧栏弹审批卡 → 回复送回会话。
- 验收：基线有记录；`pnpm --filter @agent-hud/desktop exec tauri build --bundles app` 产物能启动；审批卡往返一次成功。

### 阶段 5 多智能体接力（2026-11-05 改定，推翻原草案「不做传话和接力」）

- 角色：Claude 做事，ChatGPT 聊天审核（主角），Codex 测试。驿窗自己当中转站，不走 Orca（常浩实际用的是 Claude 桌面版、Codex 桌面版和 ChatGPT 网页，不在 Orca 终端里开会话）。
- 接力：一个任务的协作单位，把这一轮里的 Claude、ChatGPT、Codex 会话绑成一组（按各自会话 id，一个会话同时只属一组），记录角色、轮次、转交记录；可多组并行。2026-11-05 常浩定：
  - 发起以「在 Claude 里说一句」为主（Claude 调驿窗工具，自己写背景交代），侧栏回执「转给…」为辅；
  - 审核时新建 ChatGPT 会话，统一放进 ChatGPT 项目「驿窗审核」、标题用任务名；之后的往返都在这两个会话里接着聊；
  - ChatGPT 读不到本机代码：背景交代默认带改动本身（过长带摘要 + 关键片段 + 完整改动作附件），常浩的 ChatGPT 已装 GitHub 连接器，另附 PR 链接。
- 三条通道：
  - Claude：agent-hud 插件通道（已有），会话空闲时自动发。
  - ChatGPT：常浩自己 Chrome 里登录的 chatgpt.com + 驿窗 Chrome 插件（不上架，开发者模式加载）。插件按驿窗下发的「接力会话名单」工作：只读、只报名单里的会话（网址 `/c/<id>`），能新开会话并回报 id、按 id 送话（标签页没开就在后台打开）、接力标签页归入「驿窗接力」标签组；经 Chrome Native Messaging 与驿窗通话，不开网络端口。插件不通时退回「复制到剪贴板 + 打开 ChatGPT」。
  - Codex：ChatGPT 桌面版本地通道 `thread-follower-start-turn` / `steer-turn`（驿窗回答 Codex 提问已在用后者），先往已有会话送话；外部新建 Codex 会话待实测。不通时退回复制并跳转。
- 分批：批 0 插件探针（#95，已完成）→ 批 1：1b ChatGPT 通道（#99）、1c 接力与发起（#71，转交单乙）、1a Codex 送话 → 批 2 自动往返（#72，轮数上限默认 2、审核写「结论：通过」即停；2026-11-06 常浩定不另做进度条，只在展开卡上标「自动往返」并加暂停 / 继续，规则见 `docs/chatgpt-channel.md`「自动往返」）。
- 接力界面重做（2026-11-06 常浩定稿，设计稿 https://claude.ai/artifact/VReXNsQ2gUc6RPRmtcvdXB 第 2 版）：左滑发起（三版共用）+ 乙·侧栏传信弹出卡 + 甲·时间线展开卡，回执上的转交单撤掉。分四批：A 数据与展开卡（#120：接力每步记录、阶段、去重、超时与重启恢复、不猜会话、ChatGPT 回执能弹出、甲展开卡、「接力 1/2」入口）→ B 左滑发起 → C 传信动效 → D 往 Codex 送话（1a）。批 C 于 2026-11-07 改定（#171，设计稿 https://claude.ai/artifact/1VZALBQ4q2HuPJdiDoVbhp 第 2 版「定稿」），取代「乙·侧栏传信弹出卡」：「乙的纸飞机 + 甲的票根印章」——按接力新步骤飞一次（发出 Claude→ChatGPT，回信飞回，送不到半路掉落），约 2.5 秒、航线收窄，停在侧栏时只动小人；ChatGPT 票根处理中盖蓝色「审」章，接力处于「已回复」时 Claude 票根角上显示红蜡「回」，之后消失（2026-11-07 #218 改为和「审」同一枚蓝色方章、盖在 Claude 脚上，脚换接力纸，见 docs/chatgpt-channel.md）；不做进度细票签。
- Orca：不在接力链路上，留作「后台工厂」（多 worktree 并行出方案、批量机械活、长时间无人值守任务）；以后可加「Orca 后台 worker」成员，暂不做。
