# ADR-0001 工作场所契约 Lite

- 状态：已采纳（2026-11-14）
- 来由：常浩 2026-11-14 要求全面审核侧栏结构：「claude，codex，GPT，deepseek 这四个本质上是一种性质，都是我的工作场所，而 hermes 单独是一个」。审核报告 `docs/design/驿窗结构审核-2026-11-14.html`；ChatGPT 思维评审成熟退出，决策记录 `docs/design/2026-11-14-工作场所契约.md`；常浩在侧栏回「按修订推荐开工」（C1–C7 按修订推荐定）。
- 术语见根目录 `GLOSSARY.md`。

## 背景

侧栏各层大多已共用组件，但每家的派生数据在 `model.ts` 各写一个分支；等你、在跑、刚回复、出错、接力这几样，在票根、展出卡、悬停概览里有的家有、有的家缺。同一类问题已经逐家各修过（撤卡、接力转回、跳回会话、在跑标记、小人动效、纸张墨色）。

## 决定

驿窗是跨 AI 的个人工作状态控制台。Claude、Codex、ChatGPT、DeepSeek 是同一种**工作场所**；Hermes 是**飞书工作台**，界面保持现状，只共用健康 / 异常的表达。

1. **结构**：来源适配器（每家按自己的协议读，允许按来源分支）→ 统一的前端派生视图（不存盘）→ 现有共用组件。不建事件总线、状态机框架、插件框架。
2. **身份**：工作场所 → 工作实例（会话，带观察通道，如 Codex App 与 Claude 拉起的 `codex exec` 审查分开）→ 工作项。接力是独立记录，各家按参与关系引用（`handoffFor`），角色（执行方 / 审核方）属于接力，不属于工作场所。
3. **工作项状态**：等你 / 在跑 / 刚回复 / 出错；「等你」再分等你、待核对、已处理三态：
   - 等你：有明确的用户动作义务（审批、提问、等你回复），证据仍有效。
   - 待核对：曾经在等，但观察器失联或日志静默，看不清。不当成空闲，也不当成可点的审批。
   - 已处理：作答、撤回、确认终止。Claude 钩子审批的进程一结束，答复就送不回去，算终止（保留 #251）。
   - 时间只影响排序和分组，不决定去留。用户可以手动忽略单条，忽略只收起提示，不改真实状态，有新证据再提示。
   - 未读回复、刚完成、审核意见自动转回中、观察器不知道的，都不算「等你」。
4. **能力四态**：不支持 / 未启用 / 观察失联 / 正常无事。失联不显示成 0 或空闲；不支持的不提示。
5. **界面**：操作路径是票根 → 外层展出卡 → 内层接力卡；悬停小收据和整张看板是并行的概览通道。所有入口读同一份工作项、用同一优先级。外层卡共用一个卡头；纸飞机样子按 #341/#344，只在这张卡对应的会话或这一家确有关联接力时出现，多条给列表，绝不回落到别家的接力。
6. **个性化白名单**：小人与动效、印章颜色、脚印读数、ChatGPT 对话 / 审核两栏的内容、DeepSeek 余额、Hermes 整块。共用界面里，白名单外的地方不按来源名分支。
7. **回执停留**不变（4 秒收起 / Hermes、ChatGPT 看过才收），实现改成每家一个配置项。
8. **验收**：`src/packages/hud/test/scenes/` 的固定场景（合成数据，不含私人内容）是共同依据——
   - 状态契约测试 `workplace-contract.test.ts`：现状还不满足的条目写成 `todo` 并注明缺陷编号，哪批修好就转正；
   - 场景预览台 `src/packages/hud/preview/`（`pnpm --filter @agent-hud/hud run scenes`，127.0.0.1:1480，`?scene=&panel&light&still`）：用真实组件渲染各场景，替代每轮临时搭的 `preview-xxx` 脚手架；
   - 三版 UI 预览用同一组场景，只比布局和信息密度，不各自定义状态。

## 拍板项（C1–C7，常浩按修订推荐定）

C1 看板会话并进各家区块、顶部保留全局「等你」汇总；C2 纸飞机扩到所有外层卡、只进关联接力；C3 小收据加「等你 · 在跑 · 接力」一行、失联写「看不清」；C4 按第 3 条三态、不做 24 小时折叠和一键清；C5 回执停留行为不变；C6 出错回执，偶发一张、持续阻断挂到恢复，按来源 + 会话 + 错误类型合并；C7「今天已回复」暂缓。可见的界面变化仍先出三版预览。

## 分批

0 契约、固定场景、预览台（本 ADR，#349）→ 1 修与契约无关的 bug → 2 统一数据与状态（含随它修的 B1–B4、B8、B9，补 Codex「完成」「提醒」钩子）→ 3 三版预览后统一界面 → 4 Hermes 边界与整体验收。接力文件里的缺陷等 #347 合并后再做。

## 后果

- 新增一家或一种能力时，补适配器和场景，不再逐层逐家补界面。
- 后端的观察器规则（如「等你」不因 30 分钟静默消失、两个观察器不互相覆盖）由 Rust 测试守，第 1、2 批补。
- 重开条件：固定场景复现显示 Codex / DeepSeek 的观察通道给不出工作项；或真实使用中仍频繁出现「该在却不在」的等待。
